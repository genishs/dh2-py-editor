# 등장공업치 (신조 가능 공업 수치) 테이블 위치 분석

## 1. 사용자 힌트
- 슬롯 0 의 SHIP (idx 16) 등장공업치 = **1000**
- 슬롯 0 의 CHEO (idx 22) 등장공업치 = **1000**

## 2. 결과 — KOUKAI2.DAT 슬롯 0

### 2-1. SHIP=CHEO=1000 (uint16 LE 직접) 매칭
- KOUKAI2.DAT, MAIN.EXE 어디에도 **0건**

### 2-2. SHIP=CHEO=동일값인 25-원소 u16 LE 후보 (모든 슬롯 동일 = 정적 글로벌)

| 슬롯내 offset | SHIP/CHEO | 25개 값 |
|---|---|---|
| **`+0x06FEB`** ★ | **100/100** | `[85, 50, 10, 15, 25, 30, 50, 37, 52, 12, 25, 82, 88, 18, 68, 67, 100, 270, 110, 95, 30, 270, 100, 42, 23]` |
| `+0x0717F` | 200/200 | `[3, 30, 85, 59, 220, 18, 70, 290, 90, 40, 20, 1050, 180, 30, 55, 130, 200, 35, 130, 135, 2, 140, 200, 300, 230]` |
| `+0x071DF` | 20/20 | `[2, 2, 12, 6, 5, 5, 70, 12, 5, 4, 10, 45, 6, 40, 16, 18, 20, 38, 42, 42, 40, 32, 20, 210, 120]` |

### 2-3. 단위/스케일 가정

| 가정 | 일치 후보 |
|---|---|
| 저장 = 표시 (1000 == 1000) | ❌ 없음 |
| **저장 × 10 = 표시** (저장 100 → 표시 1000) | **`+0x06FEB`** ★ 가장 자연스러움 |
| 저장 × 50 = 표시 | `+0x071DF` |
| 저장 × 5 = 표시 | `+0x0717F` |

## 3. 가장 유력한 위치 — `slot + 0x06FEB`

## 4. Python 구현 가이드

```python
KOGYO_OFFSET_IN_SLOT = 0x06FEB   # ⭐ 1순위 (×10 스케일 가정)

def read_kogyo(state, slot=None):
    """state.fp 에서 슬롯의 등장공업치 25개 읽음. slot=None 이면 state.page 사용."""
    page = state.page if slot is None else slot * 33340
    state.fp.seek(page + KOGYO_OFFSET_IN_SLOT)
    return list(struct.unpack("<25H", state.fp.read(50)))

def write_kogyo_one(state, idx, stored_value, slot=None):
    page = state.page if slot is None else slot * 33340
    state.fp.seek(page + KOGYO_OFFSET_IN_SLOT + idx * 2)
    state.fp.write((stored_value & 0xFFFF).to_bytes(2, "little"))
    state.fp.flush()

# 사용자에게 표시 시: stored * 10
# 사용자가 입력 시: stored = input // 10
```

## 5. 사용자 추가 검증 단계

다른 함선의 등장공업치를 게임에서 확인하면 단번에 확정:

| 함선 | `+0x06FEB` ×10 예상 | `+0x071DF` ×50 예상 | `+0x0717F` ×5 예상 |
|---|---|---|---|
| BALS (0) | **850** | 100 | 15 |
| KARA (9) | 120 | 200 | 200 |
| JUNK (17) | 2700 | 1900 | 175 |
| GWAN (24) | 230 | 6000 | 1150 |

## 6. 결론

- **유력 추정**: `slot + 0x06FEB` (uint16 LE × 25). 저장값 × 10 = 게임 표시값.
- **MAIN.EXE 동기화 필요**: `MAIN.EXE @ 0x42722` 의 표 A (이전 분석가 C) 는 `+0x071DF` 와 동기화된 같은 데이터의 ROM 사본. 새 게임 시작 시점의 등장공업치는 MAIN.EXE 에서 슬롯으로 복사되어 들어옴.
- **확정 사유 부족**: SHIP=CHEO=1000 직접 매칭이 없어 ×10 스케일 가정 필요. 사용자 추가 검증이 §5 표로 단번에 확정 가능.
